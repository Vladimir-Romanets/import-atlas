# Migrating from 0.15 to 1.0: `tree` and `graph` swap places

1.0 renames the CLI commands **and** the library exports so that one word
means one thing throughout: `tree` is the tree, `graph` is the graph. This
affects everyone — CLI users and library consumers alike.

## ⚠️ Read this first

Two renames cross over each other, so the old names stay *valid* while
meaning something else. Nothing throws; you get the wrong report.

- `import-atlas graph entry.ts` used to write the **tree**. It now writes the
  **graph**.
- The library's `renderGraphHtml` used to render the **tree**. It now renders
  the **graph**, and takes a `GraphData` (from `buildGraph`) rather than a
  `TreeNode[]` (from `buildForest`) — so a library call at least fails to
  type-check, while the CLI silently does something else.

Search your scripts and CI for `import-atlas graph` before upgrading.

## Why

Both names were on the wrong report. The command called `graph` drew a tree
per entry file, while the graph — every file drawn once, with an edge from
each importer — was called `merged`. The library repeated the mismatch: the
export *without* "graph" in its name (`renderHtml`) backed the command called
`graph`, and the export named after "graph" backed `merged`.

1.0 names each report after what it draws, and every export after the command
that produces it.

## CLI

| Before | After | Report |
| --- | --- | --- |
| `import-atlas graph` (default) | `import-atlas tree` (still the default) | tree per entry file |
| `import-atlas merged` (alias `dag`) | `import-atlas graph` (alias `dag`) | one graph, every file once |
| `import-atlas all` | unchanged | both |
| `import-atlas scan` | unchanged | raw JSON |

Running `import-atlas entry.ts` with no command still writes the tree, as
before.

### Output files and flags

| Before | After |
| --- | --- |
| `import-graph.html` (tree) | `import-tree.html` |
| `import-graph-merged.html` (graph) | `import-graph.html` |
| `all --out-merged <file>` | `all --out-graph <file>` |
| `all --out-tree <file>` | unchanged (new default `import-tree.html`) |

`import-graph.html` now holds the **graph**, not the tree. Update any
`.gitignore`, publish step or link that names it.

Default titles change too: `Import Tree` for `tree`, `Import Graph` for
`graph`. `all` takes one `--title` (default `Import Atlas`) and appends each
report's own kind — `" (tree)"` or `" (graph)"` — where 0.15 appended
`" (merged)"` to one of them and left the other bare.

```diff
-import-atlas graph src/index.ts --root . --open
+import-atlas tree src/index.ts --root . --open

-import-atlas merged src/index.ts --root . --open
+import-atlas graph src/index.ts --root . --open

-import-atlas all src/index.ts --out-merged dag.html
+import-atlas all src/index.ts --out-graph dag.html
```

Every other flag — `--root`, `--tsconfig`, `--exclude`, `--max-files`,
`--max-cycle-length`, `--json`, `--open` — is unchanged, including the
higher `--max-files` default (10000) the graph command carries.

## Library

| Before | After | Report it produces |
| --- | --- | --- |
| `renderHtml` | `renderTreeHtml` | tree — CLI `tree` |
| `RenderOptions` | `TreeOptions` | options for `renderTreeHtml` |
| `renderGraphHtml` | `renderGraphHtml` ⚠️ **different report** | graph — CLI `graph` |
| `RenderGraphOptions` | `GraphOptions` | options for `renderGraphHtml` |
| `RenderData` | `TreeRenderData` | the tree viewer's embedded payload |

There are no deprecated aliases for the old names — update call sites
directly.

```diff
-import { scan, buildForest, renderHtml } from "import-atlas";
+import { scan, buildForest, renderTreeHtml } from "import-atlas";

 const result = scan(["src/index.ts"], { root: process.cwd() });
 const forest = buildForest(result);
-const html = renderHtml(forest, result, { title: "My app" });
+const html = renderTreeHtml(forest, result, { title: "My app" });
```

```diff
 import { scan, buildGraph, renderGraphHtml } from "import-atlas";

 const result = scan(["src/index.ts"], { root: process.cwd() });
 const graph = buildGraph(result);
 const html = renderGraphHtml(graph, result, { title: "My app" });
```

The second example is unchanged on purpose: `renderGraphHtml` kept its name
and its meaning is now the one the name suggests. What breaks is the *other*
call — code that passed a `buildForest` result to `renderGraphHtml` has to
move to `renderTreeHtml`.

If you only imported types:

```diff
-import type { RenderOptions, RenderGraphOptions, RenderData } from "import-atlas";
+import type { TreeOptions, GraphOptions, TreeRenderData } from "import-atlas";
```

`buildForest`, `buildGraph`, `scan`, the three Findings detectors,
`GraphData`/`GraphNode`/`GraphEdge`/`GraphRenderData`/`TreeNode`, and every
other export are unaffected.
